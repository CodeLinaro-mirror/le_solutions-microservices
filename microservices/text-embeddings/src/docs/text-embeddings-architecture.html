Text Embeddings Service

Architecture, end-to-end flow, and interface documentation for the microservices/text-embeddings service. The service exposes an OpenAI-compatible embeddings API, resolves model assets from configuration, tokenizes input text, executes a QNN-backed embedding graph, and returns vectors plus usage metadata to callers.

1. Architecture Overview

API Layer

Hosted by the generated OpenAPI / FastAPI server in src/web-api/openapi_server. The external contract is the embeddings endpoint implemented by EmbeddingsApiImpl. Additional endpoints (/models, /health, /ping) are provided by their respective implementations.

Inference Layer

The active embeddings runtime is SimpleQnnEmbeddingApp in impl/text_embed_qnn.py. It loads tokenizer assets, inspects QNN binary metadata, creates input and output tensors, executes the graph, and decodes the output vector. A secondary runtime, QnnSampleApp, exists in impl/qnn_runtime/sample_app.py but is not used by the live API path.

Configuration Layer

Model identity and binary selection are resolved through model_config_manager from configs/models_config.json, combined with runtime environment variables: MODELS_PATH, TOKENIZER_DIR, QNN_BACKEND_LIB, QNN_SYSTEM_LIB, and optional QNN_* overrides.

This microservice is an embeddings generator only. It does not contain a vector database, document index, or semantic search engine. Its responsibility is request handling, model resolution, inference execution, and response formatting.

4. Interface

Service boundaries, request and response shapes, dependencies, and interactions with adjacent components.

External Boundary

  • Primary external interface: HTTP JSON embeddings API.
  • Client-facing implementation: EmbeddingsApiImpl.create_embeddings().
  • The service accepts a model identifier and one or more text inputs.
  • The service returns embedding vectors and token usage counts.
  • The service does not expose native QNN details to callers.
  • Additional endpoints: GET /models, GET /health, GET /ping.

Internal Boundary

  • API layer delegates inference to SimpleQnnEmbeddingApp.
  • Blocking inference is isolated in a worker thread via asyncio.to_thread().
  • Model lookup is delegated to model_config_manager.
  • Tokenizer resolution depends on filesystem assets and environment variables.
  • QNN execution depends on native provider libraries being available at runtime.
  • Tensor dump logging writes to /tmp/log_qnn-python.txt via utils_dump.dump_tensors().
CategoryDetails
Request Inputs model (string, required), input (string or list of strings, required), dimensions (integer, optional, truncates output vector), encoding_format ("float" or "base64", optional, default "float").
Derived Inputs Model binary path from MODELS_PATH and models_config.json. Tokenizer assets from TOKENIZER_DIR. Backend and system libraries from QNN_BACKEND_LIB and QNN_SYSTEM_LIB. Optional graph, input, and output name overrides from QNN_GRAPH_NAME, QNN_INPUT_NAME, QNN_OUTPUT_NAME. Padding token from QNN_PAD_TOKEN. Verbose mode from QNN_VERBOSE.
Response Outputs object ("list"), data (list of Embedding objects, each with index and embedding vector), model (echoed model ID), usage (prompt_tokens and total_tokens). Embedding vectors are float lists or base64-encoded float32 byte strings depending on encoding_format.
Error Responses HTTP 400 if the requested model is not in models_config.json. HTTP 500 for unexpected runtime errors. Errors are logged via LoggerConfig before being returned.
Dependencies libQnnHtp.so (or override), libQnnSystem.so (or override), QNN binary model file, tokenizer assets (tokenizer.json, *.model, or custom .py), Python packages: fastapi, pydantic, tokenizers or sentencepiece (optional), numpy (optional).
Tokenizer Discovery Auto-discovery order: (1) tokenizer.json (HuggingFace format), (2) *.model (SentencePiece), (3) *.py with an encode(text) function (custom). All resolved from TOKENIZER_DIR.
Logging Service-level logging via LoggerConfig (Python standard logging, INFO level, stdout/stderr). Tensor-level debug logging via utils_dump.dump_tensors(), which appends to /tmp/log_qnn-python.txt using the print_to_log decorator. Tensor dumps are written before and after graphExecute() in _run_single().
Concurrency The FastAPI event loop handles HTTP concurrency. Each embeddings request spawns a worker thread via asyncio.to_thread(). A new SimpleQnnEmbeddingApp instance is created per request and closed after use. Multiple input strings within a single request are processed sequentially inside the worker thread.
Interactions with Other Components The service is self-contained and does not call other microservices at runtime. It is consumed by external callers (RAG pipelines, search services, analytics) that POST text and use the returned vectors. It is deployed via Docker Compose using the compose files in deploy/ and src/docker-compose.yaml.
